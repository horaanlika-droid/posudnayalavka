# Посудная лавка 🍷

Веб-витрина (в стиле Telegram / адаптирована под iPhone) + Telegram-бот с админ-функциями
для интернет-магазина посуды и бокалов.

## Что внутри

- **Веб-приложение** (Next.js, App Router) — каталог, корзина, оформление заказа,
  чат поддержки, оплата.
- **Оплата**: GRAM (крипто-кошелёк), ЮKassa (карты/СБП), счёт для юр.лица (скачиваемый HTML-счёт).
- **Чат поддержки**: открывается на сайте, все сообщения дублируются админу в Telegram,
  админ отвечает прямо из бота реплаем, ответ уходит клиенту на сайт.
- **Бот** (grammY) — админ-панель: /orders, /order N, смена статусов кнопками, сводка каталога, /chat.

Хранилище — простые JSON-файлы в `./data` (атомарная запись), одной ВПС-процесса достаточно.
При желании легко заменить на SQLite/Postgres (слой в `src/lib/db.ts`).

## Запуск

```bash
npm install

# разработка
npm run dev        # веб на http://localhost:3000

# прод
npm run build
npm start          # веб
npm run bot        # Telegram-бот (отдельный процесс, polling)
```

Бот и веб читают **одну и ту же папку `./data`** — запускай их из одной директории проекта.

> На VPS удобно держать два процесса: `npm start` и `npm run bot`
> (например через systemd / pm2 / supervisor).

## Настройка (переменные окружения)

Скопируй `.env.example` в `.env` и заполни **свои** значения на сервере.
В коде секретов нет — всё берётся из окружения.

| Переменная | Что это |
|---|---|
| `PUBLIC_URL` | Публичный адрес сайта (для вебхуков и возврата после оплаты) |
| `BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_ID` | Telegram-id админа (числом). Новые заказы/чаты приходят ему |
| `BOT_MODE` | `polling` (по умолчанию) или `webhook` |
| `CURRENCY` | `RUB` |
| `GRM_API_BASE`, `GRM_API_KEY`, `GRM_RECEIVER` | Ключи кошелька GRAM |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Ключи ЮKassa |
| `ORG_*` | Реквизиты юр.лица для счёта (название, ИНН, КПП, БИК, счёт, банк, ФИО руководителя…) |

**Демо-режим:** пока не заполнены ключи GRAM/ЮKassa, оплата имитируется успешной
(страница `/pay/simulate`), чтобы можно было проверить весь поток. После ввода ключей
включится реальная оплата.

### Вебхуки провайдеров (когда заполнишь ключи)

- **ЮKassa**: укажи в личном кабинете вебхук на
  `{PUBLIC_URL}/api/payments/yookassa/webhook` — заказ помечается оплаченным по событию `payment.succeeded`.
- **GRAM**: формат колбэков зависит от провайдера кошелька. Адаптируй `src/lib/payments/gram.ts`
  и приёмник `{PUBLIC_URL}/api/payments/gram/callback` под свой API (там же можно включить проверку подписи).

### Вебхук бота (опционально)

По умолчанию `BOT_MODE=polling` — ничего настраивать не надо.
Если нужен webhook — в .env `BOT_MODE=webhook`, `PUBLIC_URL`, `BOT_WEBHOOK_SECRET`
и пропиши webhook в Telegram API на URL веб-процесса (роут бота уточни в `src/bot`).

## Каталог

Товары и цены — в `src/data/catalog.ts`. Цены в копейках (`priceMinor`, 1990 = 19,90 ₽).
Бокалы с несколькими объёмами/наборами — через `variants`. Картинки — абсолютный URL или `public/img/…`.
Заполняй только этот файл — цены нигде больше не дублируются.

## Структура

```
src/
  app/            страницы и API-роуты (Next)
  bot/index.ts    Telegram-бот (grammY)
  data/catalog.ts каталог (товары/цены/бокалы)
  lib/
    env.ts        переменные окружения
    db.ts         JSON-хранилище
    orders.ts     заказы
    support.ts    чат поддержки
    notify.ts     уведомления админу
    payments/     gram.ts, yookassa.ts
```
